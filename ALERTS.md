## Design in one paragraph
One pipeline: listing published/edited -> write a small event row -> match the listing against saved searches (reverse query on indexed location keys + category + rent/sale + price; keywords checked in memory; unique record per user/listing/type) -> route per person (always in-app inbox; push if a live device; email digest as fallback; quiet hours; cap of 10 instant alerts a day) -> send and log with tracked links. A scheduler calls `/internal/jobs/:name` for retries, held pushes, digests, weekly agent reports and expiry warnings. Vercel Hobby cron runs only once a day, so use an external trigger (Cloudflare Worker cron or GitHub Actions).

## Collections
New: `saved_searches`, `alert_events` (30-day expiry), `notifications` (inbox + delivery log, 90-day expiry), `listing_stats_daily` (180-day expiry), `area_follows`. Extend: `notification_settings` (timezone, language, quiet hours, digest hour, per-type switches), `device_tokens` (user id, last_seen_at, app_version, language).

## Constraints
- Pilot stage, no revenue: stay on free tiers; WhatsApp is paid per message (about $0.062 marketing, $0.0101 utility in Nigeria) so it is out of the first release.
- Android and iOS apps (React Native, Expo) are planned: keep tokens platform-neutral, put a https://proptriz.com link in every alert, one Firebase project for all platforms.
- All user-facing strings in English, French and Swahili.
